# 1.2.8 变更与验证状态

> 说明：每一项都标了**当前验证状态**。凡标「待确认」的，都是代码已改但还没有经过实际使用验证的。

## 新功能

### 1. CF 验证失效时自动提示重新验证

打开 nhentai 时若遇到 403（Cloudflare 拦截），插件会：

- 在页面上弹出提示卡片，说明需要重新验证
- **自动打开一个小窗口**到站点首页，供你完成人机验证
- 验证完成后，失败的图片会自动重试，不需要刷新页面

**状态：已确认可用**（验证流程能正常走完）

**已知限制：验证窗口需要手动关闭。**
程序化关闭在这个场景下不可靠（详见下方「验证窗口自动关闭」），所以保留手动关闭。

## 修复

### 2. 打开 NH 作品需要刷新一次才正常

首次打开时页面可能只渲染了一半（`.num-pages` 的壳在、数字还没填），旧逻辑只判断元素存在就当作就绪，解析出 0 页直接报错。

现在：结构检测会校验内容（页数须为正），并在 init 前用当前 DOM 重建解析器重试，最多约 4 秒。

**状态：已确认（用户反馈未再遇到）**

### 3. 一次弹出多个验证窗口

冷却原来是按 URL 分开算的，并发失败的是不同图片页、URL 各不相同，等于每个都放行。

现在：全局时间戳，60 秒内最多弹一次；且冷却写进 `sessionStorage`，页面刷新后依然有效。

**状态：已确认（用户实测无问题）**

### 4. 加载失败只显示「请刷新」，要手动点

退避重试（1s → 1s → 2s → 3s → 5s → 5s）用尽后，旧代码直接 return，把活推给用户。

现在：用尽后固定**每 5 秒重试一次，无限重试**，不刷新页面。

**状态：已修复（用户反馈"NH 有时会停止重试，要手动点"）**
原因：`scheduleAutoRetry` 开头有 `if (!isActive()) return`，而 isActive 表示
「这页是否在视口附近」——用户滚去别页时正在失败的页被永久放弃。
已去掉该门槛。

### 5. 超分失败的页永久不再超分

`SuperResolutionService.failed` 原本是永久黑名单——网络抖一次失败，这页就再也不会超分（实测 66 页只有 21 页成功）。

现在：失败记录带时间，15 秒后允许重试；并加了「原地重试」定时器，停在某页不动也会周期性再试。

**状态：已确认（超分能覆盖全部页面）**

### 6. 统计浮层看不到超分分布

**新增**：超分分区底部有一行页序号色块，绿色 = 已超分（在缓存里），黄色 = 正在渲染，只显示这两种。缓存淘汰后色块消失，能直接看出哪页被丢掉了。

**状态：已确认（运行正常）**

### 7. WNACG 部分页面不生效

- 域名只认 `wnacg.com` → 现在支持 `.com / .ru / .net / .org`
- `photos-view-id-*.html` 不被识别 → 已经识别

**状态：已确认（阅读页正常）**

### 8. WNACG 整本视图（photos-view-id）报 404

这类页面是**逐页导航**：每页一个独立 HTML，页 id 不连号，靠 `var nextpage` 串起来，服务器不提供 `photos-item-aid-*.html` 列表。

现在：从当前页沿 `nextpage` 链走到底，逐页取 `#picarea` 图片（上限 500 页 + 防环）。

**状态：算法已按站点源码实现（md5 与分块数已用 Python 交叉验证）；
用户反馈已修复。**

### 9. 右下角全屏按钮 / 页码条样式不对（18comic、joyacg）

宿主站点的全局 CSS（Bootstrap 的 `button { }`、`div { }`）漏进插件，导致按钮变形。

现在：**插件整体挂到 Shadow DOM**，宿主样式物理上无法进入。这也是从根上解决「每遇一个新站就要适配一次」的做法。

**状态：部分确认**（错误面板渲染正常，说明隔离生效；按钮/开关尚未逐个确认）

### 10. 设置里的开关滑块跑出轨道（18comic）

Bootstrap 改了 `div` 的盒模型和间距，而 `.switch` 依赖 `width: 28px` + `margin: auto` 居中。

现在：`.switch` / `.track` / `.thumb` 的尺寸、定位、边框全部钉死。

**状态：用户发现与浏览器缩放比例有关，暂按已知行为处理**

### 11. joyacg 画面整体偏右

根因是**缩略图侧栏占位**：`.thumb-panel.side` 折叠时只把 `opacity` 归零、宽度仍占 `thumbSizePx`（200px）。宽度 ≥767px 时侧栏展开（`showBookThumbView`），画面就被推右。

现在：没有缩略图数据就不展开侧栏；joyacg 不再生成缩略图。配合 Shadow DOM 后应彻底消失。

**状态：已确认修复**

### 12. 图片被横向拉伸（joyacg / wnacg / 禁漫）

书页模式按 `height = width × heightOfWidth` 排布，且 `img { height: 100% }` 填满容器——比例偏小一点就会被横向拉伸。

根因是各平台把 `heightOfWidth` 写死成 1.4，而真实值多为 `1807/1280 = 1.4117`，差 0.84%。

现在**统一在渲染层兜底**：图片一加载出来就用 `naturalWidth/naturalHeight` 覆盖该页比例，任何平台（含以后新增的）自动生效。

**状态：已确认修复**（joyacg / wnacg 像素级一致；禁漫也已修复）

### 13. 打开禁漫要等很久

`init` 里串行处理全部 30 页（下载 → 解码 → canvas 还原 → 编码），一页 0.5~1 秒，整本要等半分钟。

现在：`init` 只登记地址，**显示某页时才处理那一页**，结果按页缓存，同页并发复用同一个 Promise。

**状态：已确认修复**

### 14. 禁漫图片是破碎的（scramble 混淆）

站点把每张图水平切成 N 条倒序写回，N 由 `md5(aid + 页码)` 末位的 charCode 决定（逐页不同，实测 14 / 12 / 8 条）。

现在：内置 MD5 算出块数，按站点算法恢复（首条承担余数，余数加在目标位置）。

**状态：已确认修复**

### 15. 打开插件后，宿主页面的滚动条还在且能拖动

只锁了 `body.overflow`，而宿主把滚动容器挂在 `html` 上。

现在：`html` 与 `body` 同时锁，关闭时还原。

**状态：已确认修复**

### 16. 同一份资源被加载两遍

插件开着时，宿主页面的图片仍在下载（它并不显示）。

现在：打开插件时把宿主 `<img>` 的 `src` 暂存到 `data-ehunter-saved-src` 并摘除，用 `MutationObserver` 拦截后续插入；关闭时原样恢复。**只动 img，不碰 iframe**（Cloudflare Turnstile 容器需要完好）。

**状态：已确认修复**

### 17. 「拉绳」开关在阅读器打开时还叠在页面上

现在：`toggleEHunterView` 里同步显隐，打开时 `display: none`，关闭时恢复。

**状态：已确认修复**

### 18. 新增 JoyACG 平台

`joyacg.cc` / `joyacg.top`。作品页是纯数字路径，一页铺开全部图片，图源是 nhentai 的 gallery 经 `wp.com` 代理。

实测 83 页，与页面标注的「頁數：83p」一致。

**状态：已确认（页数、标题正确；比例已确认像素级一致）**

### 19. 新增禁漫天堂平台

`18comic.vip` / `18comic.ink` / `jmcomic-zzz.one` / `jmcomic-zzz.org` / `comic18j-susu.com` / `comic18j-nico.work` / `comic18j-neo.com`

一页铺开全部图片（`readmode = "read-by-full"`），图片经 scramble 混淆。

**状态：待确认**

## 明确放弃 / 已知限制

### 验证窗口无法自动关闭

试过四种方案，均不可靠：

| 方案 | 失败原因 |
|---|---|
| `fetch` 探测是否通过 | 探测请求本身也被挑战，永远 403 |
| 读 `window.open` 返回引用的 `document.title` | Edge 上 `window.open` 常返回 `null` |
| 用 `window.name` 识别验证窗口 | **`window.name` 在跨域导航后被清空**（CF 会跳到 `challenges.cloudflare.com` 再跳回） |
| 给验证窗口 URL 加标记参数 | 带 query 的首页让 CF 走另一条路径，出现「验证 → 跳回 → 又验证」循环 |

**结论：保留手动关闭。** 验证完成后关闭窗口即可，失败的图片会自动重试。
